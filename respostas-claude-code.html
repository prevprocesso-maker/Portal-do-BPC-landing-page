Respostas do Claude Design ao Claude Code.

Definições do sistema de marketing conjunto — CarlosCostaPrev + Portal do BPC. Documento de referência pro Claude Code construir a automação em cima. O Nike faz a ponte.

Divisão de trabalho: Claude Code automatiza, deploya e integra. Claude Design gera conteúdo, copy e visual. Quem publica/agenda é o Claude Code (Meta Business Suite). Quem aprova é o Carlos.
1Formato de entrega do conteúdo

Pode ser estruturado — entrego JSON pra automação e HTML pra humano aprovar.

HTML quando é pra ler / aprovar / virar PDF (como o plano de 30 dias). Pra você consumir no código, entrego JSON com este schema por post:

{
  "id": "2026-06-01-am",
  "data": "2026-06-01",
  "turno": "manha",          // manha | tarde
  "horario": "08:30",
  "conta": "portaldobpc",    // portaldobpc | carloscostaprev | facebook
  "formato": "carrossel",    // carrossel | reel | post_imagem | card | pergunta | story
  "coluna": "voce_tem_direito",
  "persona": "P2",
  "gancho": "...",
  "legenda": "...",
  "slides": ["...", "..."],  // só quando formato = carrossel
  "cta": "...",
  "hashtags": ["#BPC", "..."],
  "grupo_fb": true,          // se gera variante pra grupo
  "versao_grupo": "..."      // texto adaptado, sem hashtag (ver item 4)
}

Se preferir Markdown com front-matter, também faço — mas JSON é o que recomendo pra parsear direto.

2Blog × Social — integração

Sim, automático, com roteamento por site.

Quando o blog publicar, eu gero a legenda do Instagram correspondente. Regra de conta:

  • Artigo de portaldobpc.com.br → @portaldobpc
  • Artigo de carloscostaprev.com.br → @carloscostaprev
  • Tema carro-chefe (BPC, aposentadoria por incapacidade, auxílio por incapacidade) → gera pras duas contas, com ângulos diferentes (uma popular, outra técnica).
3Menção cruzada mensal

1 cross-mention por semana, por ponte temática — não por contagem de posts.

Em vez de "a cada 4 posts", a regra é 1 menção cruzada por semana, sempre quando o tema faz ponte natural (ex.: post de incapacidade no @carloscostaprev → "se for por deficiência, veja também o @portaldobpc").

Pra deixar determinístico no código: dispare a cross-mention sempre na quinta-feira, 1 por semana.
4Grupos de bairro — estrutura

Variante separada — não é o mesmo texto do Instagram.

O "▶ GRUPO FB" vem no campo versao_grupo: sem hashtags, mais informal, mais curto, sem "link na bio" (grupo não tem bio) e com CTA adaptado pra "chama no WhatsApp / comenta aqui". Serve pra grupo de Facebook e de WhatsApp.

5Canva — quem cria os visuais

Eu faço o design, no estilo da marca.

Produzo carrosséis e cards em HTML e consigo exportar pra Canva editável ou PDF/PNG. O Carlos não desenha do zero — recebe a arte pronta e só ajusta se quiser. Eu entrego texto + visual; você cuida do agendamento e deploy.

O que eu não faço: publicar/postar sozinho. Quem agenda é o Claude Code no Meta Business Suite.
6Calendário recorrente

Estrutura fixa, conteúdo dinâmico.

O esqueleto se repete todo mês: ritmo 2/dia (manhã autoridade + tarde emoção), as 6 colunas editoriais, blog na quarta, batch no domingo. O que muda a cada mês: o tema das 4 semanas, os ganchos e as datas comemorativas.

Construa o sistema dinâmico no conteúdo, fixo no template. Combinado: todo dia 25 eu entrego o JSON do mês seguinte.

7Grupos de WhatsApp / Facebook — volume

Sem lista no momento — fica em aberto, a levantar com o Nike/Carlos.

Não há lista nem número definido agora. No plano deixei os critérios de busca dos grupos; a lista real é levantamento manual. Quando existir, peça ao Nike: (a) quantos grupos, (b) Facebook vs WhatsApp, (c) tamanho médio.

Recomendação de arquitetura enquanto não há lista: trate como distribuição manual assistida — eu entrego o texto pronto por grupo (versao_grupo), o colar é manual. Não implemente disparo automático em massa no WhatsApp: queima número e fere os termos. Quando a lista existir, a gente reavalia.
